# The server may be asked to close quiet channels, and is not asked by default

[ADR-0009](0009-quiet-is-a-view-of-the-participants.md) made *quiet* a view rather than a state, and in the same breath refused closing on idle: a clock, a threshold to argue about, a sweep on the server, and a wait ended that nobody asked to end. Thirteen days later the live server holds 41 channels, 19 open and every one of them quiet, 14 of them for a week or more; they arrive at about one and a half a day, all of them handoffs. The rail folds them, which is what the ADR set out to do, and the pile still grows under the fold: `saneha list` prints every one as an open row, and the heading's count only goes up. The person running the server asked for a way to have them closed after a number of days of their choosing.

This ADR says yes to that, on narrower terms than the one it revisits refused, and the terms are the decision.

**It closes on quiet, not on idle.** Quiet is read the way the rail reads it, including [ADR-0012](0012-quiet-needs-a-second-arrival.md)'s clause: a handoff nobody has taken has one join and is waiting, not quiet, and the sweep leaves it. The thing ADR-0009 could not accept was a `saneha wait` woken by a close nobody made — a participant parked in a channel that had merely gone silent. Quiet is not silence. It is *nobody present*, and a waiter is present: `wait` does not leave, so a channel somebody is waiting in is never quiet, and never among what this closes. The clock only starts when the last participant has left, and the sweep measures from the newest message, because the last thing to happen before a channel goes quiet is a leave, and a leave is a message. So no held wait is ended here that its holder did not walk away from first. What is left of the ADR-0009 objection is the clock and the threshold, and both of those are now somebody's to set rather than the code's to assume.

**It is off unless asked, and the asking is the operator's.** `saneha serve --close-quiet-after <DAYS>`, or `SANEHA_CLOSE_QUIET_AFTER`, in the same place `SANEHA_BIND` and `SANEHA_DB` are set — a fact about this server, set by whoever runs it, in the Quadlet unit. Without it the server behaves exactly as before: nothing closes, nothing expires, quiet stays a view. That is why this does not overturn ADR-0009. The default is still that a state is not decided by the server, and a person who turns this on has decided, once, that on their server a channel nobody has been in for that many days is over. There is no fixed number in the code for anyone to argue with, and the one thing the flag will not spell is zero, because closing a channel the moment it goes quiet is closing a handoff on receipt, which [ADR-0005](0005-a-handoff-is-a-message-and-a-leave.md) refused and this ADR does not reopen.

**What is accepted by turning it on.** A closed channel refuses joins and has no `reopen`, and [ADR-0003](0003-no-authentication.md) is still why there cannot be a person-only one. So an untaken handoff older than the threshold is closed before anybody picks it up, and a taken one is closed before a third session that would have carried on in the same channel gets there. The transcripts say how often either happens. Of the three handoff transcripts read for this ADR, the one return to a taken channel came a day after the receipt, and nothing came back later than that; fourteen of the nineteen quiet channels hold exactly six messages, which is a handoff and its receipt and nothing more, and say the same without being read. One channel had never been taken at all, and it crossed the seven-day mark on the day this was written. That is the cost, stated so the number can be chosen against it: a threshold is a claim that after so many quiet days the work has moved on, and a week is comfortably longer than any return the transcripts show.

**It is the same close.** Each channel is closed by the write `saneha close` makes — state, `closed_at`, and one `close` system message — with the server named in the body where an identity would be and the threshold beside it: `saneha closed the channel, quiet for 7 days`. The transcript's one line for a close says who and why, the viewer draws the struck hash and "closed at" it already knows how to draw, and no verb, message kind, column or migration is added. Every close in one sweep is one transaction, so a sweep that fails halfway closes nothing rather than some. A viewer following a channel that is closed this way is woken as it would be by any other close.

**It rides the sweep that is already there.** The server has swept unbound attachments at start and hourly since [attachments existed](../../CHANGELOG.md); this runs on the same tick, so a threshold crossed while the server was down is acted on as it comes up rather than an hour later. `/health` reports `close_quiet_after_days` — the number, or `null` — so a person looking at a close nobody made can tell a server that was asked to make it from one that was not.

## Alternatives that were weighed

- **A person-run batch** — `saneha close --quiet --older-than 7d`, asked twice the way `delete` is, run by hand or from a routine on a laptop, which is where [ADR-0002](0002-wake-is-outside-the-server.md) puts automation. It keeps the server without a clock, and it was the recommendation. It was not what was wanted: the point is that nobody has to remember to run it, and a routine on a laptop that is closed for the night is not a server that is up. The server already has the clock; it uses it for attachments.
- **`saneha list` folding quiet channels** the way it folds closed ones. Cheaper still, and it answers the listing and nothing else; ADR-0009's own consequence says the CLI listing will not hide open channels, and this ADR leaves that where it is.
- **Deleting on the clock.** No. A transcript is the only record of what was handed off, and `delete` stays manual and asked twice.

## Consequences

- **Nothing changes for a server nobody configures.** The flag is absent from the deployed unit until the person deploying it adds it, and `/health` says which it is.
- **The threshold is operational, not a design constant.** It lives in the unit next to `Image=`, changes with a restart and no build, and `docs/deploy.md` says how. A future that wants a different number, or none, edits one line.
- **ADR-0009's fold is unchanged**, and still what a browser sees for the channels under the threshold. What this adds is that, on a server so configured, the Quiet heading has a ceiling on how many days a row stays under it.
- **The skill says nothing about it**, on purpose. An agent that finds a handoff channel closed is told so by `join`'s refusal, as it would be for any closed channel, and the person carrying the name is the one who decides whether to make a new one. Nothing an agent does changes because the server might close a channel it has already left.
- **Tests hold the boundary rather than the clock.** `tests/quiet.rs` backdates transcripts and asks the store directly, and seeds a database before a server configured with the threshold opens it, so the start-up sweep is what is tested; the hourly tick is the one attachments already ride and is not re-tested here.
