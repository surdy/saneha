# Quiet is a view of the participants, not a state of the channel

[ADR-0005](0005-a-handoff-is-a-message-and-a-leave.md) gave each handoff a channel of its own and wrote down what that would cost: channels accumulate, nothing expires, `delete` is manual and asked twice, and one channel per handoff reaches that sooner than one per project. It arrived. The rail filled with conversations that were over, and the only tool to hand was `close`, which that ADR had already ruled out for this: `close` refuses joins (`open_channel_id` in `store.rs`, "nobody can join it"), ends every held wait at once with exit 4, and has no inverse, so closing a handoff on receipt strands the next session that has to carry the work on and takes away the person's one follow-up question. The want was never a way to end these channels. It was a way to stop looking at them.

So the rail folds away the channels that are open, have a transcript, and have nobody present. That is *quiet*, and the load-bearing part is that it is not a state. No column, no verb, no system message, nothing written when a channel enters it or leaves it. `quiet()` in `web/index.html` reads it off the channel each time the rail is drawn, from a `present` count that is itself a correlated subquery over the participants folded into `CHANNEL_COLUMNS` in `store.rs` — so neither end stores it. One join makes a channel not quiet, and because nothing was decided there is nothing to undo. That property is the whole design: a fold you can be wrong about costs a click, where a state you can be wrong about costs a migration or a verb.

Every alternative needed something to be decided. Auto-closing when the doc is taken is ADR-0005's refusal verbatim, and nothing about it has changed. Closing on idle — nothing said for a week — needs a clock, a threshold to argue about, and a sweep on the server, and it ends waits: a participant parked on `saneha wait` in a channel that had gone quiet by the clock would be woken by a close nobody asked for. Presence answers what idleness was a proxy for and answers it exactly, without a clock that can be wrong: a channel somebody is waiting in has a participant that has not left, so it is never quiet.

A state would also have needed a way out, and there is nothing to copy. `close` is one way and there is no `reopen`; adding one is not the small thing it looks, because [ADR-0003](0003-no-authentication.md) means no verb can be person-only — anything that can undo a state can be run by any agent that can reach the server, including the one whose `leave` put the channel there. A fold in the rail needs no such verb. It is kept per browser under `saneha.quiet`, beside `saneha.closed` and `saneha.pins` and for the same reason ADR-0005 refused a mode: which conversations you are done looking at is a fact about the person looking and not about the channel. The two keys are separate on purpose, since wanting the finished conversations in view is not the same as wanting every channel nobody is in.

The signal was already half there. `leave` marks a participant away, and *away* has meant "not woken" since participants existed, which is migration 2; *present* is its complement, so the only new thing is the count, and `present` rides on every channel the server describes rather than only on the listing, because it is a fact about the channel in the way `newest_id` is. The other half is a sentence in `skills/saneha/SKILL.md`: the session picking up a handoff now leaves after posting its receipt, so both sides have left and the channel goes quiet by itself instead of waiting for somebody to tidy it.

One guard earns its place. A channel minted a moment ago and joined by nobody also has nobody present, and folding it would hide a channel from the person who has just made it and is looking for it — the worst thing this could do, and a case a fixture with no unjoined channel in it would never reach. So the transcript has to have started: `newest_id > 0`. A channel with nothing in it is new, not quiet.

## Consequences

- **Nothing is added to the schema, and no verb or message kind is added to the wire.** The change is `web/index.html`, one field on `Channel` in `src/api.rs` filled by the subquery in `src/store.rs`, and a line of the handoff recipe in the skill with the paragraph under it. `present` defaults on deserialisation as `newest_id` does, so a client meeting a server that predates the field reads 0; the page and the server that serves it are always the same build, so nothing that matters reads that 0 as "nobody present".
- **`saneha list` does not group them, and is not going to.** A fold is for an eye that is on the rail all day and has something to click; a listing is printed once and read once, and a CLI that hid channels behind a heading nobody can open would be hiding them. The `--json` view was never filtered and still is not.
- **The retention question is answered for the eye and not for the disk.** Quiet channels are still there, still hold their transcripts and attachments, and still cost a `delete` each to remove. ADR-0005 also named one long-lived channel per repository as the other answer, and [handoffs.md](../handoffs.md) now says how to ask for one — at the cost that ADR named, a transcript that mixes unrelated work.
- **A quiet row is drawn as an ordinary open row.** No struck hash, no mark of state, because nothing was closed — the struck hash says a channel takes no more messages, and this one does. The cost is that with the group open there is nothing on the row to say why it is under that heading; the participants column, one click away, is where "everyone has left" is visible.
- **Nobody has looked at the Quiet heading in a browser.** The rail is held by the Node harness in `tests/rail.js`, which runs the page's own script over a DOM small enough to fit in that file and asserts the HTML the page produces — the fold, the count, the order, the forced-open rule, and the minted channel that must not be swallowed. That is a check on what the page emits, not on what a person sees. The harness carries a channel nobody has joined and a listing of none because a bug once shipped in one of those, which is the argument for the fixture the guard above is held by — and none of it is a pair of eyes.
